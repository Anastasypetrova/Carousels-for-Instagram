# Входящие материалы

Сюда кладутся фотографии, видео и текст.

## Несколько постов сразу

Сделайте папку на каждый пост — материал можно сгружать пачкой и разбирать
потом:

```
input/
├── kapstadt/
│   ├── IMG_4821.HEIC
│   ├── IMG_4822.HEIC
│   └── text.md
├── studio/
│   ├── IMG_5003.jpg
│   └── text.md
└── zima/
    └── …
```

В спеке поста укажите папку в поле `source`, и дальше на фотографии можно
ссылаться просто по имени:

```json
{ "slug": "kapstadt", "source": "kapstadt", "slides": [{ "photo": "IMG_4821" }] }
```

Так `IMG_0001` из одной съёмки не спутается с `IMG_0001` из другой. Если имя
встречается в нескольких папках, а `source` не указан, рендер остановится и
покажет, между чем выбирать — угадывать он не станет.

Можно и без папок, просто свалив всё в `input/`. Для одного поста так быстрее.

## Обложка и порядок

Первый слайд — тот, что видно в ленте, поэтому кадр для него выбираете вы.
Помечать нужно **только его**, остальные файлы оставляйте как есть.

- **переименуйте в `cover`** — `cover.HEIC`;
- **или поставьте единицу в начало имени** — `1 IMG_4821.HEIC`;
- **или просто скажите** агенту: «обложка — та, где закат».

Ничего не указали — агент выберет сам и скажет, какой кадр поставил первым.

## Что класть

| | |
|---|---|
| Фото | `.jpg`, `.png`, `.webp`, `.avif`, `.heic` |
| Видео | `.mp4`, `.mov` |
| Текст | `text.md` — одним куском, разбивку по слайдам сделает агент |

Имена файлов любые, переименовывать ничего не нужно: регистр, пробелы и знаки
препинания при поиске не учитываются.

## Приватность

Содержимое этой папки не попадает в git — в репозиторий уходят только код и
правила. Ваши исходники остаются на вашем компьютере.
