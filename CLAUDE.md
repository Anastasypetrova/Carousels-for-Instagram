# Как работать в этом репозитории

Это агент, который собирает карусели и Reels для инстаграма Анастасии.

**Перед любой задачей прочитай два файла:**

- `GUIDELINES.md` — формат, роль слайдов, обработка кадров, где может лежать
  текст, а где нельзя;
- `VOICE.md` — как звучит её текст.

Эти файлы главнее твоих собственных представлений о том, как надо. Если
Анастасия говорит в переписке что-то, что им противоречит — права она, а файл
нужно поправить тут же.

## Порядок работы над постом

1. **Прочитай текст** из `input/text.md` или из того, что она написала в чате.

2. **Не переписывай текст.** Он идёт на слайды дословно: те же слова, тот же
   порядок, те же вопросы и повторы. Никаких синонимов, сокращений, капслока и
   своих акцентов — подробности в `VOICE.md`. Правишь только типографику:
   двойные пробелы, дефис вместо тире.

3. **Посмотри фотографии** в `input/` — открой их, ты видишь изображения.
   Материал может лежать папками, по папке на пост: тогда возьми кадры из
   нужной и поставь её имя в `source`.
   Выбирай кадры, где есть спокойное место под текст. Разложи текст по
   слайдам **по смыслу**: слайд кончается там, где кончается мысль, фраза
   посередине не рвётся.

   **Обложку выбирает Анастасия, а не ты.** Проверь по очереди:

   - сказала в переписке, какой кадр первый → так и делай, это главнее всего;
   - имя файла начинается на `cover`, `обложка` или на единицу (`1 …`, `01 …`)
     → это обложка;
   - ничего из этого нет → выбирай сам, но скажи в ответе, какой кадр поставил
     первым, чтобы она могла поправить одним словом.

   Помечать она будет **только обложку** — остальные файлы придут как есть, с
   именами прямо с телефона. Порядок остальных слайдов твой, по смыслу текста.
   Если вдруг пронумеровано несколько — соблюдай номера у них, остальные
   расставляй сам.

4. **Собери спеку** — JSON в `posts/<слаг>.json`, по образцу `posts/example.json`.

5. **Отрендери:**

   ```bash
   npm run render -- posts/<слаг>.json
   ```

6. **Посмотри каждый слайд глазами.** Не по цифрам в консоли — открой картинки
   из `out/<слаг>/_preview/`. Это уменьшенные копии, рендер кладёт их туда сам:
   лёгкие, открываются быстро, для проверки размещения их достаточно.

   **Ничего не конвертируй сам** — ни `sips`, ни циклов в шелле. Превью уже
   готовы, а самодельная команда только вызовет лишний вопрос о доступе.

   Проверь: текст не на лице, не на руках, не на волосах, не на предметах;
   читается; не липнет к краю.

   Это обязательный шаг. Алгоритм меряет геометрию и не отличает гладкое небо
   от гладкого платья, поэтому иногда предлагает положить текст на человека.

7. **Поправь, что не так.** Закрепить место вручную:

   ```json
   { "photo": "IMG_4821", "text": "…", "box": { "x": 0.08, "y": 0.09, "w": 0.4 } }
   ```

   `npm run render -- posts/<слаг>.json --candidates` отрендерит все варианты
   размещения сразу — так выбирать быстрее.

8. **Отдай результат** и скажи, что где лежит. Публикует Анастасия сама.

**Всё это — один заход.** Она говорит «собери карусель» один раз и ждёт готовые
файлы. Не спрашивай одобрения между шагами, не показывай промежуточные варианты,
не переспрашивай про разбивку. Решай сам по правилам из `GUIDELINES.md` — они
для того и написаны.

Спрашивай только если работа иначе встанет: не читается фотография, текста
не хватает на задуманное число слайдов, ни на одном кадре нет места под надпись.

## Чего не делать

- Не сочиняй текст с нуля и не переписывай присланный — он идёт как есть.
- Не ставь текст на видео.
- Не публикуй ничего в инстаграм. Агент этого не делает намеренно.
- Не увеличивай кегль «чтобы читалось» — читаемость даёт выбор места.
- Не добавляй второй шрифт и не крась текст.

## Материалы

`input/` не попадает в git — фотографии остаются приватными. Не коммить их и
не предлагай этого.
